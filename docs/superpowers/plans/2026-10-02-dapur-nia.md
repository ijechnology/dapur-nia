# App 2 Dapur Nia Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Membangun aplikasi web mobile-first App 2 Dapur Nia untuk katering rumahan berbasis Vite + React (TypeScript), Tailwind CSS, Shadcn UI styling preset b1dnAsE2Km, dan Cloud Firestore dengan integritas data ketat sesuai PRD Sesi 3.

**Architecture:** Single Page Application (SPA) mobile-first dengan Bottom Navigation (Menu, Pelanggan, Pesanan, Laporan). Logic bisnis dan state machine transisi diisolasi ke modul validasi independen yang diuji dengan TDD. Akses Firestore menggunakan Firebase SDK v10+ modular dengan konfigurasi dinamis in-app dan fallback .env.

**Tech Stack:** Vite, React 18/19, TypeScript, Tailwind CSS, Lucide React, Cloud Firestore, Vitest untuk unit tests.

**Spec:** `docs/superpowers/specs/2026-10-02-dapur-nia-design.md`

## Global Constraints
- Bahasa antarmuka: Bahasa Indonesia (jelas, fungsional, active voice).
- Desain anti-AI slop: palette hangat utilitarian (Umber/Brick `#C85A32`, Charcoal `#1C1E1B`, warm surface `#FAFAF8`), tanpa all-caps palsu, tanpa generic gradient washes.
- Invarian Harga: > 0.
- Invarian Sisa Porsi: integer >= 0 (0 = status Habis).
- Invarian Nomor WhatsApp: Unik pada koleksi pelanggan.
- Invarian Porsi Pesanan: > 0 dan <= sisa porsi menu.
- Invarian Total Tagihan: sum(subtotal) + ongkir (> 0, tidak boleh minus).
- Mesin Status: `menunggu_pembayaran` -> `dikonfirmasi` -> `diproses` -> `dikirim` -> `selesai` (atau `dibatalkan` dari `menunggu_pembayaran`). Tidak boleh melompat atau mundur.

## Review Focus
1. Input harga menu negatif atau 0 (harus ditolak dan form menampilkan pesan perbaikan).
2. Input nomor WhatsApp duplikat (harus ditolak sebelum disimpan ke Firestore).
3. Pembuatan pesanan dengan porsi 0 atau melebihi sisa porsi menu (harus ditolak).
4. Usaha mengubah status pesanan melompat atau mundur (tombol UI dibatasi dan validator menolak).
5. Perhitungan laporan harian saat ada pesanan dengan status 'dibatalkan' (pesanan dibatalkan tidak boleh masuk ke omset atau jumlah porsi).
